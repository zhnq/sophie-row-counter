# 最多三条围巾的首页与保存方案

这份方案将小工具从单作品计数改为本机最多保存三条作品。每条围巾拥有独立的设置、颜色和行记录；首页用于选择作品，计数页继续承担逐行操作。沿用现有配色、水平正视预览和简洁文案。

容量按保留的作品总数计算：进行中和已完成都占名额，未确认的新建草稿不占名额。本方案已在 v0.6.0 实现，验证结果见 [多围巾与首页审查](release-audit-v0.6.0.md)。

## 首页

标题为“我的围巾”，旁边一行显示“1 / 3 条”。作品纵向排列，最近打开的一条排在最前，其余保持稳定顺序。只有实际保存的作品，没有空白占位卡，也不增加筛选页或底部标签栏。

每条作品展示名称、更多按钮、按实际参数生成的水平围巾预览，以及一行进度。预览沿用所选纱色和织物纹理，呈现这条计划的完整形状；进度另用文字显示，不把完整预览误称为已经织出的实物。

| 作品状态 | 进度文案示例 | 操作 |
| --- | --- | --- |
| 正在织整条围巾 | 16 / 328 行 · 接下来第 17 行 | 继续织 |
| 整条记录全部完成 | 328 / 328 行 · 已完成 | 查看记录 |
| 只记录一个阶段且全部完成 | 加针段已完成或减针段已完成 | 查看记录 |
| 记录无法读取 | 记录无法读取 | 重试 |

更多菜单只放“围巾设置”和“删除围巾”。名称通过现有设置修改。删除前显示作品名，并明确设置和进度将一起删除，按钮为“取消”和“删除”。

| 保存数量 | 首页状态 | 新建入口 |
| --- | --- | --- |
| 0 条 | 标题和开始按钮 | 开始一条围巾 |
| 1–2 条 | 显示实际作品 | 新建围巾 |
| 3 条 | 显示三条作品与容量 | 管理围巾 |

“管理围巾”打开简短的作品列表，用户选择要删除的一条，再确认删除。保存删除成功后才释放名额；不自动替换最旧、最近未打开或已完成的作品。无须提供不受三条限制的隐藏归档区。

## 打开与切换

每次启动先进入首页，避免多作品时默认进入另一条围巾。切到后台再回来时保持当前页面和当前行，不强制回首页。

点击“继续织”进入该作品的第一个未完成行，并居中显示。下一行不能用已勾选总数加一计算，因为用户可以跳行勾选。

计数页顶部保留返回首页的入口，显示当前作品名；点击作品名可以打开最多三条作品的切换列表，显示名称、纱色和简短进度。切换后定位各自当前行，保持已完成记录。首页和快速切换使用同一份作品数据。

设置与预览页不放作品切换入口。用户先保存修改或取消回到计数页，再切换，避免把一条作品的未提交草稿带到另一条。

## 新建与调整

新建流程为：首页 → 新建围巾 → 围巾预览 → 开始计数。新建草稿与现有作品分开；最后确认保存成功后才创建作品并占用一个名额。取消或返回修改不影响其他作品，也不会留下空白作品。

修改设置和“设为最宽处”继续使用现有预览确认流程，只更新对应作品。颜色、织法、密度、转折行和首减行都独立保存。已有织行的保护规则继续生效。

保存失败停留在当前界面，原作品和其他作品不变。快速重复点击确认不会创建两条相同作品；最终提交时重新检查容量，不只在首页判断。

## 旧记录与存储

旧的单条围巾自动作为第一条作品保留，沿用名称、颜色、原行表规则、转折参数以及完整的勾选行号，不仅保存“已完成多少行”。迁移先验证旧数据，再写入新的作品库；保留旧存档备份，不重复导入。

每条作品使用稳定的独立 ID，不能用名称、颜色或列表位置定位保存目标。修改、计数、转折、删除都明确指定 ID。库中保存最近打开的 ID；首页的针数、形状、当前行和完成状态从作品原始数据计算，不另存容易失去同步的摘要。

单条损坏的记录保留占位并占用名额，不静默丢弃；其他正常作品仍可打开。整个库或版本无法读取时显示错误，不当作空库创建默认记录覆盖。多个标签页通过 IndexedDB 共享事务串行保存；同一作品使用版本号拦截陈旧修改，其他作品更新和最终容量校验由自动检查验证。

本版仍为本机保存，不加入账号、联网同步或作品分享流程。

## 实施验收

1. 旧单条记录迁移后行表、所有勾选、颜色和转折位置不变。
2. 创建三条不同颜色、参数和进度的作品，切换和重开后各自独立恢复。
3. 第四条不能保存；新建取消不占名额，失败不影响已保存作品。
4. 删除确认中展示正确作品名，取消不删除；删除失败不释放名额，成功后其他两条完整保留。
5. 设置与转折只更新目标作品；新建和切换不复用另一条的预览、勾选或转折草稿。
6. 跳行勾选时“接下来第 X 行”正确；只记录一个阶段时不误报整条围巾完成。
7. 三条作品、长名称和小屏幕下仍可滚动操作，按钮保持可辨识的触控尺寸；缩略图不拉伸围巾形状。
8. 损坏记录、保存失败、两个标签页的不同作品更新及并发新增都有明确验证。
