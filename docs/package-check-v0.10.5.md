# v0.10.5 首次存档兼容修复与打包检查

日期：2026-10-03。交付对象：小红书离线 H5 小工具 ZIP。

## 问题与证据

用户已上架旧版，小米 15 可以使用，分享给 iPhone 15 Pro Max 后首页显示“围巾记录库无法读取，请重试”，无法新建。用户补充发布时可能未勾“本地存储”。

代码复现发现：首次读取返回 `{data:''}` 会进入 JSON 解析并触发截图原文；官方示例的 `{data:null}` 路径正常。尚未取得真实 iPhone 的返回值，因此该路径是可复现的兼容疑点，不能认定已证实 iOS 平台行为。

实时官方文档本次取得的页面仍标注更新于 2026-09-22：

- [版本判断与 Storage](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s3-7)：9.46.0+ 使用平台缓存；`getStorageInfo()` 无业务参数，返回的 `keys` 为当前缓存键列表。
- [兼容基线](https://miniapp-sandbox.xiaohongshu.com/minitool/doc#s2-2)：iOS 最低 18.4。
- 官方发布页提供“本地存储”权限选项，提交为发布元数据中的授权声明。本次未更改用户发布配置；公开文档没有证明未勾选必然只影响 iOS。

## 修复

仅当平台读取返回精确的空字符串时，查询 `getStorageInfo().keys`。键列表格式正确且不包含 `sophie-scarves-v2` 时，才将其视为首次空库；随后沿用旧库迁移、写前二次读取和保存成功后更新状态的流程。

已存在该键、列表异常、查询失败或方法不可用时仍保护存档。原生请求超时后，未结束的请求继续阻止并行操作；已有平台缓存后来消失时，不重新导入浏览器旧进度。官方 `null` 空值和正常 JSON 路径不增加键列表查询。

新版 ZIP 与 v0.10.4 对比，包内只修改 `storage.js`；旧包 SHA-256 核对一致。存档键与结构保持兼容。
